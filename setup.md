# pw marks tracker setup

## 1. architecture overview
- **frontend**:
  - `index.html`, `styles.css` (or `stryles.css`), `script.js` (for students)
  - `admin.html`, `admin.js` (for teachers)
  - can be hosted on github pages, vercel, netlify, or run locally.
- **cloudflare worker**:
  - `worker.js` operates as the cors-enabled backend middleman between frontend and supabase.
  - hosted at: `https://peedabloo.desaipahal64.workers.dev`
- **database**:
  - supabase tables `studentaccount` and `studentprogress`.

---

## 2. database setup (supabase)
in the [supabase sql editor](https://supabase.com), run `sql.txt`:

```sql
create table if not exists studentaccount (
  id bigint generated by default as identity primary key,
  studentname text not null,
  studentbatch text not null,
  studentpin text not null,
  createdat timestamp with time zone default now(),
  unique (studentname, studentbatch)
);

alter table studentaccount disable row level security;

create table if not exists studentprogress (
  id bigint generated by default as identity primary key,
  studentname text not null,
  studentbatch text not null,
  studentpin text not null,
  subjectname text not null,
  chaptername text default '',
  dppprogress text default '',
  prabalprogress text default '',
  parikshitprogress text default '',
  pyqsprogress text default '',
  updatedtime timestamp with time zone default now()
);

alter table studentprogress disable row level security;
```

## 3. cloudflare worker deployment
1. open your worker at [cloudflare dashboard](https://dash.cloudflare.com).
2. replace its code with the updated `worker.js`.
3. your supabase project credentials (`defaultsupabaseurl`, `defaultsupabasekey`, `defaultadminsecret`) are already present in `worker.js`.
4. click **save and deploy**.

---

## 4. authentication system
- **log in mode**:
  - student enters **name**, **batch**, and **pin**.
  - verifies account exists and validates pin.
  - if pin is wrong or account not found, returns clear error feedback.
  - loads existing subjects and chapters.
- **sign up mode**:
  - student chooses **name**, **batch**, and **secret pin**.
  - verifies the account does not already exist (prevents duplicates).
  - creates the registered account in `studentaccount`.
  - immediately logs the student in.

---

## 5. student ui flow
1. **subjects page**:
   - if 0 subjects: shows **only 1 button**: `+ add a subject`.
   - if subjects exist: shows cards for each subject + search bar.
   - clicking a subject navigates to its chapters page.
2. **chapters page**:
   - separate page with a back button (`&larr; back to subjects`).
   - if 0 chapters: shows **only 1 button**: `+ add a chapter`.
   - if chapters exist: shows cards for each chapter + search bar.
   - clicking a chapter navigates to its progress page.
3. **progress page**:
   - separate page with a back button (`&larr; back to chapters`).
   - displays fields for **dpp**, **prabal (jee main)**, **parikshit (jee adv)**, and **pyqs**.
   - buttons to **save progress** or **delete chapter**.

---

## 6. teacher admin gui
1. open `admin.html` and unlock with admin password (`topsecret`).
2. **students directory**: shows every registered student with total subjects & chapters count.
3. **delete student account**: click the delete button beside any student name in the directory or on their profile header to delete their account and all associated progress.
4. **subjects level**: clicking a student shows their subjects and chapter counts with search.
5. **chapters level**: clicking a subject shows all chapters in that subject with search.
6. **progress level**: clicking a chapter displays progress cards for dpp, prabal, parikshit, and pyqs.
