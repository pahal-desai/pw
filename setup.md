# pw marks tracker setup

## 1. architecture overview
- **frontend**:
  - `index.html`, `styles.css` (or `stryles.css`), `script.js` (for students)
  - `admin.html`, `admin.js` (for teachers)
  - can be hosted on github pages, vercel, netlify, or run locally.
- **cloudflare worker**:
  - `worker.js` operates as the cors-enabled backend middleman between frontend and supabase.
  - hosted at: `https://peedabloo.desaipahal64.workers.dev`
- **database**:
  - supabase tables `studentaccount` and `studentprogress`.

---

## 2. database setup (supabase)
in the [supabase sql editor](https://supabase.com), run `sql.txt`:

```sql
create table if not exists studentaccount (
  id bigint generated by default as identity primary key,
  studentname text not null,
  studentbatch text not null,
  studentpin text not null,
  createdat timestamp with time zone default now(),
  unique (studentname, studentbatch)
);

alter table studentaccount disable row level security;

create table if not exists studentprogress (
  id bigint generated by default as identity primary key,
  studentname text not null,
  studentbatch text not null,
  studentpin text not null,
  subjectname text not null,
  chaptername text default '',
  dppprogress text default '',
  prabalprogress text default '',
  parikshitprogress text default '',
  pyqsprogress text default '',
  dppphoto text default '',
  prabalphoto text default '',
  parikshitphoto text default '',
  pyqsphoto text default '',
  updatedtime timestamp with time zone default now()
);

alter table studentprogress disable row level security;

-- If your table already exists, run sql.txt in Supabase SQL editor:
alter table studentprogress add column if not exists dppphoto text default '';
alter table studentprogress add column if not exists prabalphoto text default '';
alter table studentprogress add column if not exists parikshitphoto text default '';
alter table studentprogress add column if not exists pyqsphoto text default '';
```

## 3. cloudflare worker deployment
1. open your worker at [cloudflare dashboard](https://dash.cloudflare.com).
2. replace its code with the updated `worker.js`.
3. your supabase project credentials (`defaultsupabaseurl`, `defaultsupabasekey`, `defaultadminsecret`) are already present in `worker.js`.
4. click **save and deploy**.

## 4. authentication system
- **log in mode**:
  - student enters **name**, **batch**, and **pin**.
  - verifies account exists and validates pin.
  - if pin is wrong or account not found, returns clear error feedback.
  - loads existing subjects and chapters.
- **sign up mode**:
  - student chooses **name**, **batch**, and **secret pin**.
  - verifies the account does not already exist (prevents duplicates).
  - creates the registered account in `studentaccount`.
  - immediately logs the student in.

## 5. student ui flow
1. **subjects page**:
   - if 0 subjects: shows **only 1 button**: `+ add a subject`.
   - if subjects exist: shows cards for each subject + search bar.
   - clicking a subject navigates to its chapters page.
2. **chapters page**:
   - separate page with a back button (`&larr; back to subjects`).
   - if 0 chapters: shows **only 1 button**: `+ add a chapter`.
   - if chapters exist: shows cards for each chapter + search bar.
   - clicking a chapter navigates to its progress page.
3. **progress page**:
   - separate page with a back button (`&larr; back to chapters`).
   - displays fields for **dpp**, **prabal (jee main)**, **parikshit (jee adv)**, and **pyqs**.
   - buttons to **save progress** or **delete chapter**.

## 6. teacher admin portal & task assignment
1. open `admin.html`:
   - **master admin password gatekeeper**: before anyone can create a teacher account or log in, they must enter the master admin password (`topsecret`). This ensures students who open the page cannot create accounts or delete peers.
   - **teacher login / sign up**: once unlocked with the master password, teachers log in or sign up with:
     - **teacher name**
     - **subject taught** (instead of batch)
     - **personal pin / password**
   - **server-side protection**: the backend worker requires the master admin password for `/api/teachersignup` and `/api/teacherlogin`, blocking unauthorized API calls.
   - **lock portal**: teachers can click `🔒 Lock Portal` at any time to re-lock the gatekeeper.
2. **batches directory (batch-first UI)**:
   - teachers see **batch names** instead of student names first.
   - search bar allows instant filtering by batch name.
   - each batch card shows enrolled student count and an **assign task** button.
   - clicking a batch card opens the students inside that batch.
3. **batch students view**:
   - shows all students in the selected batch.
   - back button `← all batches`.
   - each student has an individual **task** button and a **delete** button.
   - deleting a student account permanently wipes the student and displays the 4-second Thor ban hammer GIF animation overlay.
4. **task assignment**:
   - teachers can assign tasks to:
     - **entire batch** (delivered to all students in that batch)
     - **individual student** (delivered only to that selected student)
   - tasks specify title, optional instructions, and optional due date/time.
   - teachers can click **view tasks** to see and delete active assignments.
5. **student dashboard**:
   - students automatically see active teacher-assigned tasks for their batch or individual name on their dashboard.
